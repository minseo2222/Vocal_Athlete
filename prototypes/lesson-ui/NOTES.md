# 프로토 결론

질문: 레슨 진행 화면 모바일 구조 — A 풀스크린 캔버스 / B 단계 카드 / C 코치 cue+시트 / D(B+C)?

## 승자: **D — 스테퍼(B) + 코치 시트(C)** (사용자 선택)
- C가 단독으로도 선호됐으나, *진행 위치 감각 부재*가 약점.
- D는 C의 강점(운동 지시 cue 중앙=무납득 자연스러움, 피치·완료·넛지를 하단 시트로 묶음)을
  유지하고, B의 단계 스테퍼(진입✓→본운동●→쿨다운)를 얇게 상단에 얹어 *지금 어디인지*를 해결.
- 쿨다운 스킵은 시트 헤더 chip으로 명시(스킵 가능 어포던스 = 레슨 해부 ADR 정합).
- "다시?" 넛지는 시트 안 인라인 → 완료를 막지 않으며 거슬리지 않음.

## 폐기
- A/B/C 변주 + 스위처 삭제, index.html을 D 단독 레퍼런스 목업으로 축소 완료.

## 결론 / 다음
구조 확정: 헤더 → 얇은 3단 스테퍼 → cue 중앙 → 하단 시트(피치·넛지·완료).
실제 앱 코드는 이 구조를 *정식으로 재작성*(프로토 제약: 무테스트·가짜 피치). 프로토는 그때 폐기.
필요 시 ADR보다 디자인 가이드/이슈로 승격.
