**문서 버전**: v0.9 (2026-05-07)
**대상 문서**: 01-A 앱 콘텐츠 사양서 / 01-B 온보딩·안전·법무 / 01-C AI 분석 차별화 사양
**목적**: 세 사양 문서를 *프로덕션 수준*까지 끌어올리기 위한 갭 식별 및 구체적 보강안 도출
**핵심 정체성 유지 원칙**: 학술 근거(RCT 기반) · 정직성(한계 표기) · 안전 우선 · 부하↑ 압박 패턴 배제 · "진단/치료/회복" 단어 금지 · 24주 초급 범위 고수

## 들어가며 — 본 보고서의 결론적 요약

세 사양 문서는 *콘텐츠·페다고지·차별화 기능* 측면에서는 컨슈머 보컬 앱(Yousician, Vanido, SingSharp, Riyaz)을 압도하는 밀도를 갖추고 있다. 그러나 실제 출시 가능한 프로덕션 앱이 되려면 다음 다섯 갭이 결정적이다:

1. **화면·플로우·디자인 시스템 명세 부재** — 14개 훈련 카드의 콘텐츠는 정의됐으나, 실제 일일 세션 화면이 어떻게 생겼는지, 정보 위계가 어떻게 되는지, 빈/에러/오프라인 상태를 어떻게 처리하는지가 사양 수준에서 비어 있음.
2. **습관 형성·리텐션 전략의 학술적-안전적 통합 부재** — "안전 방향" 게이미피케이션의 구체적 메커니즘(streak 페널티 회피, 자율성 보장 패턴), 알림 전략, 위젯·Live Activities 활용이 사양화되지 않음.
3. **2025–2026 기술 스택 재검증 필요** — CREPE(2018) 대비 SwiftF0(2025)가 모바일에서 42배 빠르고 노이즈 견고성이 12 percentage point 우수하다는 신규 증거. VOQANet+ (2025)는 hand-crafted feature(jitter/shimmer/HNR)와 SFM 임베딩 결합형이 더 강건. 콜드스타트 전략이 부재한 점이 V1 출시의 가장 큰 기술 리스크.
4. **한국 법제 2025–2026 격변 미반영** — 디지털의료제품법(2025-01-24 시행), 디지털의료기기 가이드라인 6종(2025-05-07), AI 기본법(2026 시행), PIPA 통합 가이드라인(2024-12-31 초안). 본 앱이 **"디지털의료·건강지원기기"** 또는 **non-device wellness app** 어느 카테고리로 포지셔닝될지 결정이 시급.
5. **운영·측정·인시던트 SOP 부재** — 적색 신호 트리거의 false positive 관리, 콘텐츠 검수 위원회의 운영 주기, 분석 이벤트 사전 정의(taxonomy), A/B 테스트 인프라가 사양 수준에서 비어 있음.

이 보고서는 **6개 신규 보강 문서(01-D~01-I)** 를 제안하고, 기존 3개 문서의 §별 보강 권고를 제시한다.

### 1.1.1 추출된 7대 패턴 (본 앱 채택 권고)

1. **Headspace식 "streak 비활성화 옵션"**: 프로필에서 streak 자체를 끌 수 있게 함. 24시간 윈도우, 8시간 중복 세션 필터, 콘텐츠 대체 가능 명시. → 본 앱 정체성("압박 ↑ 배제")과 가장 정합.
2. **Duolingo식 "streak freeze + weekend amulet"**: 페널티 회피 메커니즘. Penn/UCLA "slack motivation" 연구가 학술 근거(Duolingo blog 인용). → V1.5에 도입.
3. **Nike "The Plan" 적응형 엔진**: 사용자의 "어제 얼마나 힘들었나"(perceived exertion) 응답 + 완료율 + 휴식일 패턴을 결합. → 본 앱의 자가 관찰 체크리스트 데이터를 그대로 사용 가능.
4. **Peloton "강사 톤 = 카피 톤"**: 본 앱은 강사 부재이므로, 콘텐츠 PD가 일관된 1인칭 멘토 톤을 가이드라인으로 명문화 필요(01-G 핸드북에서 다룸).
5. **Apple Fitness+ "링 닫기" 시각 메타포**: 일일 목표를 *연속 숫자가 아닌 도형 닫기*로 시각화 — streak 압박을 시각적으로 완화.
6. **Calm "5분 미니 세션"**: 시간이 없는 날을 위한 *3–5분 short 세션*. 본 앱의 14개 훈련 카드 중 일부를 "3분 압축 변형"으로 사전 제작.
7. **Down Dog "직접 구성 모드"**: 자율성(autonomy) 만족을 위한 freestyle 옵션. V1.5+에서 14개 카드 중 사용자가 골라 자기 세션 구성.

# Part 2. 01-A 앱 콘텐츠 사양서 발전 권고

## 2.1 §별 평가 및 보강 권고

### §1. 콘텐츠 제작 표준 (영상·오디오·anti-pattern)
- **평가**: 충분 — 영상/오디오 SOP·anti-pattern은 컨슈머 앱 대비 압도적.
- **보강 권고**:
  - **(2-1) 자막 표준 명시**: 한국어 자막 폰트(Pretendard/Noto Sans KR), 1줄 16자 이내, 1초 4자 이하 디스플레이 속도, 색상 대비 WCAG 2.2 AA(4.5:1).
  - **(2-2) 다각도 시점 토글 사양**: 정면/측면/입 클로즈업/상체 풀샷 4종을 동일 시점 동기화. 토글 UI는 화면 우상단 segmented control(48dp 터치 타겟).
  - **(2-3) 영상 속도 0.75x/1x/1.25x 옵션**: 음정·템포 변경은 *피치 보존 알고리즘* 사용(Time-stretch with phase vocoder, 또는 Rubberband mobile binding).
  - **(2-4) 음성 안내 톤 가이드**: 1인칭 ("우리 같이 해볼게요"가 아니라 "한 호흡 더 내려놓고 가볼게요" 식의 *코치형 평어체*). PD 핸드북(01-G)에 음성 액터 캐스팅 기준·녹음 SOP 문서화.

### §2. 자가 관찰 체크리스트
- **평가**: 부족 — 항목은 있으나 UX 패턴이 미정의.
- **보강 권고**:
  - **(체크리스트 UX 비교)**:

  | 패턴 | 장점 | 단점 | 권고 |
  |---|---|---|---|
  | 체크박스 리스트 | 빠름, 익숙함 | 강도·뉘앙스 표현 X | 단순 폼 점검에만 |
  | 1–5 슬라이더 | 강도 표현 | 정밀도 의문 | "오늘 통증 느낌"에만 |
  | 카드 스와이프(Tinder식) | 게임형, 빠름 | 한 번에 1개라 밀도 낮음 | **권고**: 세션 후 핵심 3개 항목만 |
  | 음성 응답("쉼표 없이 부드럽게 됐나요?" → 사용자 음성 답변) | 자연스러움 | ASR 오인식 위험, 처리 지연 | 접근성용으로 옵션 |

  - **(체크리스트 항목 재정의)**: 24주 Phase별로 항목 수 변동(Phase A: 4개, B: 6개, C: 8개) — 점진적 노출(progressive disclosure) 패턴.
  - **(AI 결과 ↔ 자가 응답 정합 검증)**: AI가 "과압착 의심" 신호를 보냈는데 사용자가 "편안함 5점"으로 응답하면 → "AI가 본 신호와 본인 느낌이 달라요. 어느 쪽이 맞는지는 알 수 없습니다. 다음 세션에서 함께 살펴봐요" 식의 *정직한 충돌 표시* 패턴.

### §3. UI 플로우 (온보딩·일일 세션·화면 컴포넌트)
- **평가**: 부족 — 플로우는 정의됐으나 **와이어프레임 수준 사양이 부재**. 이 부분이 가장 큰 갭.
- **보강 권고**:
  - **별도 문서(01-D 화면 플로우·와이어프레임 사양) 신설** (Part 6 참조).
  - 기존 §3에는 *원칙*만 두고 상세는 01-D로 이관:
    - 일일 세션 화면 정보 위계: ① 오늘의 목표 카드(타이머/카드 수) ② 첫 카드(워밍업) ③ 메인 카드 ④ 자가 관찰 ⑤ 세션 리포트
    - 빈 상태 처리: "오늘 첫 세션이에요" / "어제 세션이 없었어요. 괜찮아요" 톤
    - 에러 상태 처리: 마이크 권한 거부 → 안내 후 설정 딥링크
    - 한 손 조작: 핵심 CTA 화면 하단 1/3 영역 배치(Apple HIG 권고)

### §4. 14개 훈련 카드 매핑 + 풀 예시(P3-13 빨대 발성)
- **평가**: 충분 — 1개 풀 예시 있음.
- **보강 권고**:
  - **(4-1) 풀 예시 *최소 3개* 추가**: P3-13 외에 ① 호흡 카드 1종 ② 모음 모핑 카드 1종 ③ 적색 신호 트리거 시 *대체 카드* 1종 — 이렇게 3개를 추가 작성. 콘텐츠 PD 외주 시 베이스라인이 된다.
  - **(4-2) 한국어 모음 차트 부속**: 'ㅏ ㅓ ㅗ ㅜ ㅡ ㅣ' 6개 단모음과 'ㅐ ㅔ' 2개 중모음의 포만트 대표값(F1/F2)을 카드별로 명시.

### §5. 적응형 진도 로직
- **평가**: 부족 — 로직 개요는 있으나 *입력 시그널·임계값·전이 규칙*의 사양이 비어 있음.
- **보강 권고**: 다음 4-tuple 로직 명문화.

| 결정 | 입력 시그널 | 임계값 예시 | 전이 |
|---|---|---|---|
| 다음 카드로 진행 | AI 정확도 + 자가 응답 + 완료율 | 정확도 ≥ 70% 3세션 연속 | 다음 카드 unlock |
| 같은 카드 반복 | AI 정확도 < 50% 또는 자가 통증 점수 ≥ 3 | — | 같은 카드 다른 변이 추천 |
| 적색 신호 트리거 | 통증 점수 ≥ 4 또는 쉰목 신호 + 과압착 | — | 강제 휴식·콘텐츠 대체 |
| 지루함 변이 | 같은 카드 5회 이상 + 정확도 정체(편차 < 5%) | — | Schmidt&Lee 2019식 random practice 변이 |

- **평가**: 부족 — V2이므로 현재 사양은 얕음. 다만 V1 출시 후 데이터 누적 전 *원칙 수립* 필요.
- **보강 권고**:
  - 비교 리더보드 *영구 금지*. 대신 "코호트 진척도(현재 24주 차수에 N명이 함께 진행 중)" 식의 *익명 동반 표시*만 허용.

### §8. 환경 분석 모듈
- **평가**: 부족 — 환경 분석은 있으나 *UX 표현*이 사양화되지 않음.

# Part 3. 01-B 온보딩·안전·법무 발전 권고

## 3.1 §별 평가 및 보강 권고

### §1. 콘텐츠 검수 위원회
- **평가**: 충분(구성). **부족(운영)**.
- **보강 권고**:
  - **운영 주기**: 분기 1회 정기 검수 + 신규 콘텐츠 배포 전 1회 + 인시던트 발생 시 임시.
  - **결재 흐름**: PD 초안 → SLP 단독 1차 → 페다고지·음성과학자 합동 2차 → 이비인후과 자문(서면) → 위원장 최종.
  - **공개**: 위원 명단·자격은 앱 내 "About" 페이지 + 분기별 검수 결과 요약 공개(투명성 차별화).
  - **이해상충 정책**: 위원이 본 회사 주식·계약 보유 시 *해당 콘텐츠* 검수에서 회피.

### §2. 9단계 온보딩 플로우
- **평가**: 부족 — 9단계는 정의됐으나 *각 단계의 카피·드롭오프 측정·예상 소요 시간*이 비어 있음.
- **보강 권고**:
  - 업계 데이터: 5스크린 초과 시 단계당 완료율 ~15% 하락; 그러나 헬스케어 앱은 "왜 이 정보를 묻는지" 명시 시 15+ 단계도 유지. → 본 앱은 **9단계 + 진행률 바 + 각 단계마다 "왜 묻나요?" 마이크로 카피** 표준.
  - **목표 활성화 지표**: "첫 일일 세션 완료율" — Day-1 활성화 40% 이상 목표(헬스/웰니스 평균 기준 25%, 우수 45%).
  - **각 단계 예상 소요 시간 명시**: 사용자에게 "약 3분이 걸려요" 사전 고지(드롭오프 감소).

### §3. 의료 동의서 초안
- **평가**: 부족 — 초안은 있으나 *2025–2026 한국 법제 변경* 반영 필요.
- **보강 권고**: 별도 §3-1 "의료 동의서 법무 검수 체크리스트" 신설:

  - [ ] **PIPA 별도 동의 분리**: 필수/선택, 마케팅, 제3자 제공, 국외 이전 *각각 별도 체크박스*. 본 앱이 모델 학습 데이터로 활용 시 *별도 옵트인 동의*.
  - [ ] **민감정보(건강 정보) 명시 동의**: 본인이 입력하는 통증·진단 보유 여부는 PIPA "민감정보". 별도 명시 동의.
  - [ ] **만 14세 미만 *원천 차단* 또는 보호자 동의 모듈**: V1은 만 14세 이상만; 만 14세 미만 진입 시 가입 차단(보호자 동의 모듈은 V2).
  - [ ] **의료기기 아님 명시**: 의료기기법·약사법·의료법상 진단·치료·예방 목적 표방 *금지* 단어 리스트 운영.
  - [ ] **자동화 의사결정 거부권**(개정 PIPA 25조의2): AI 분석 결과만으로 사용자에게 *중대한 영향*을 미치는 결정 시 거부권 고지. 본 앱은 단순 학습 추천이라 해당 안 될 가능성 높지만 **명시적으로 적시**.
  - [ ] **데이터 이전성**(개정 PIPA): 사용자가 자신의 학습 기록을 JSON 등으로 다운로드 받을 수 있는 기능.
  - [ ] **암호화 의무**(PIPA 24조 3항): 음성 데이터 저장·전송 모두 AES-256(저장), TLS 1.3(전송).
  - [ ] **음성 녹음 IRB 표준 문구 차용**(미국 IRB 사례): "녹음의 목적·보관 기간·접근 권한·삭제 절차" 4개 항목.

### §4. 진단 보유자 정책 (거부/조건부)

- **보강 권고**:

### §5. 환경 분석 모듈

### §6. 적색 신호 자동 트리거 시스템
- **평가**: 부족 — 트리거 정의는 있으나 *false positive 관리 SOP*가 비어 있음.
- **보강 권고**: 신규 §6-1 "False Positive 관리 SOP":

  | 단계 | 행동 |
  |---|---|
  | **1차 트리거** | 즉시 세션 일시 정지, 부드러운 카피("잠시만요. 목 컨디션을 점검하고 갈게요"); 사용자에게 자가 응답 요청 |
  | **2차 분기** | 사용자 "괜찮음" 응답 + 1차 트리거 재발 없음 → 세션 재개; 단, "오늘은 강도 낮춤 카드로 진행" |
  | **3차 강제 휴식** | 사용자 "통증" 응답 또는 1차 트리거 재발 → 세션 종료 + 휴식 콘텐츠(centering·브레스 워크) 자동 대체 |
  | **데이터 로깅** | 모든 트리거 익명 로그(원인 추정·사용자 응답·후속 행동); 월 1회 위원회 검토 |
  | **임계값 조정** | 분기별 false positive율 모니터링; > 20% 시 임계값 재보정(콜드스타트 시 보수적으로 시작) |
  | **사용자 피드백 루프** | "불필요한 알림이었나요?" 1탭 피드백 — 학습 데이터로 |

### §7. 잘못된 폼 자동 감지
- **평가**: 충분(원리). 부족(UX 차별).
- **보강 권고**:
  - 적색 신호와 *별도 채널*: 폼 감지는 *제안*이지 *강제 정지*가 아님. 카피 톤 차이 명시.
  - 카메라 기반 폼 감지(자세·턱 위치 등)는 V2; V1은 *오디오 기반*만(과압착·과기식 신호).

### §8. 데이터 프라이버시 (한국 PIPA)
- **평가**: 부족 — 2024–2025 PIPA 개정 사항(통합 가이드라인 초안 2024-12-31) 반영 필요.

  - **CPO 지정**: PIPA상 의무. 3년 이상 개인정보 보호 경력자.
  - **PIA(Privacy Impact Assessment)**: 음성 데이터 + 건강 민감정보 결합이라 *시행 권고*.

  - **국외 이전 금지 원칙**: 가명정보의 국외 이전은 원칙적 금지(2025 PIPA 강화). → 모든 처리 한국 리전.

### §3. MVP 범위 (V1)
- **평가**: 부족 — **콜드스타트 문제 미해결**.
- **보강 권고 (§3-1 신설 — 콜드스타트 전략)**:

  V1 출시 시점에 옵트인 코호트 데이터가 *0건*이다. fine-tuning 없이 어떻게 차별화 기능을 작동시킬 것인가?

  | 차별화 기능 | 콜드스타트 전략 |
  |---|---|
  | **3분류 발성(과기식/균형/과압착)** | ① 공개 데이터셋 사전 학습(PVQD, SVD, AVPD 등 — 라이선스 확인 필수) ② 한국어 라벨링은 자체 큐레이션(SLP 위원 + 검수 위원회 50–100시간 라벨링) ③ V1은 *3분류 분류기 + 신뢰도 점수 ≥ 0.7만 표시*; 그 이하는 "분석 보류" UX. |
  | **VOQANet+ 변형** | ① 영어 PVQD 사전 학습 모델 사용 ② 한국어 보정은 hand-crafted feature(jitter/shimmer/HNR)로 보강 ③ "베타" 라벨 명시 |
  | **한국어 검증** | ① 검수 위원회 직접 녹음 100세트 시드 데이터 ② 옵트인 코호트 모집 베이스라인 |
  | **마이크 한계 정직 표기** | 콜드스타트 영향 X — 즉시 가용 |
  | **웨어러블(V3+)** | 별도 — V3 이전 미적용 |

  - **베이스라인 모델 평가 메트릭**:
    - 3분류: macro F1 ≥ 0.65 (3-class) 베이스라인, V1 출시 후 1년 내 0.75 목표.
    - 피치 정확도(SwiftF0): RPA(Raw Pitch Accuracy) ≥ 90% in clean, ≥ 80% in 20dB SNR.
    - VOQANet+ MOS 예측: PCC ≥ 0.7(영어 PVQD), 한국어 검증 후 PCC ≥ 0.5(콜드스타트 baseline) → ≥ 0.7 목표(1년).
  - **사용자 가시성**: 신뢰도 < 임계값 시 "분석 결과를 보여드리지 않습니다 — 정확도가 충분하지 않아요" *정직 표기*. 이것이 차별화 메시지의 핵심 증거.

### §4. 평가 메트릭
- **평가**: 부족 — 메트릭은 있으나 *모니터링 SOP* 부재.
- **보강 권고**: §4-1 신설 "모델 모니터링·재학습 SOP"
  - 주간 자동 리포트: 신뢰도 분포, 거부율(분석 보류율), 오버라이드 이벤트.
  - 월간 위원회 검토: 모델 성능 + 사용자 피드백 충돌 케이스(자가 응답 ↔ AI 결과 불일치).

  - **드리프트 모니터링**: 입력 분포(예: 다른 한국어 사투리, 다른 마이크 분포) 변동 감지 → KS-test, PSI(Population Stability Index).

```
[옵트인 코호트 참여 동의서 v0.1 초안]

제목: ○○ 한국어 보컬 학습 앱 학습 데이터 자발적 기여 동의

1. 본 동의의 목적
당신이 본 앱에서 녹음한 음성·자가 응답·세션 기록을 익명화하여 본 앱의 AI 모델 학습에 활용하기 위한 자발적 동의입니다. 본 동의는 본 앱 사용과 무관하며, 동의하지 않아도 모든 기능을 동일하게 사용할 수 있습니다.

2. 무엇을 모으나요?
- 음성 녹음 (각 세션의 핵심 5–10초 클립)
- 자가 관찰 응답 (1–5 척도)
- AI 분석 결과 (피치 편차, 발성 분류, 환경 점수)
- 디바이스·OS·마이크 모델 정보 (성능 보정용)

3. 무엇을 모으지 않나요?
- 이름, 전화번호, 정확한 위치
- 의료 진단 정보 (별도 동의 시에만)
- 신용·결제 정보

4. 어떻게 보호하나요?
- AES-256 저장, TLS 1.3 전송
- 화자 식별 정보 분리(가명 ID 매핑은 별도 안전 저장소)
- 음성 임베딩 저장 후 원음은 30일 내 폐기 옵션
- k-anonymity ≥ 5 보장 (인구통계 군집)

5. 누가 보나요?
- 본 회사 ML 엔지니어 (가명화된 형태)
- 분기 1회 검수 위원회 (집계 데이터만)
- 외부 연구자에게 *공개*는 별도 동의 후 익명 코퍼스 형태로만

6. 동의 철회
```

# Part 6. 신규 보강 문서 제안

기존 3개 문서로는 프로덕션 사양을 다 담기 어렵다. 다음 6개 신규 문서를 제안한다.

## 6.1 01-D 화면 플로우·와이어프레임 사양

**목적**: 모든 화면의 와이어프레임·정보 위계·인터랙션을 사양 수준으로 명문화.

**목차 골격**:
1. 디자인 토큰(컬러·타이포·스페이싱) 인덱스 (01-F 참조)
2. 정보 아키텍처 — 탭 구조·딥링크 매핑
3. 9단계 온보딩 와이어프레임 (각 단계: 헤더·바디·CTA·"왜 묻나요?"·예상 소요 시간·드롭오프 측정 지점)
4. 일일 세션 플로우 와이어프레임 (대시보드 → 추천 → 카드 1 → 카드 N → 자가 관찰 → 리포트)
5. 14개 훈련 카드 화면 컴포넌트 (영상 플레이어, 다각도 토글, 실시간 피치 시각화, 적색 신호 알림 모달)
6. 진도 대시보드 (월/주/일 뷰, 변화 시각화 카드)
7. 빈 상태 / 에러 상태 / 오프라인 상태 모음
8. 다크모드·접근성 변형
9. 위젯·Live Activities 사양 (iOS Live Activities 4KB ContentState 제약, Android Glance 대응)
10. 마이크로 인터랙션 (햅틱·사운드 큐) 표

## 6.2 01-E 알림·리텐션 전략

**목적**: 압박 ↑ 없이 습관 형성을 돕는 알림 전략.

**목차 골격**:
1. 원칙 — "조용한 알림"·SDT autonomy 보장·푸시 옵트아웃 권리
2. 알림 카테고리 (학습 리마인더, 적색 신호 후속, 콘텐츠 업데이트, 결제·계정)
3. 시간·빈도 — 1일 최대 1회 학습 리마인더, 사용자 지정 시간대 ±1h, 미완료 시 재푸시 X(Headspace식)
4. 카피 가이드 — 한국어 톤 매트릭스(격려/중립/정보), 금지 표현 리스트
5. streak 알림 — 기본 OFF, 옵션 ON 시 비파괴적 메시지
6. Day-1·Day-3·Day-7 리텐션 후크 (퍼스널라이즈드 first-week journey)
7. 무료 → 유료 전환 — *프리미엄 기능 일시 체험* 패턴(loss-aversion 활용 X, "더 큰 음역" 같은 부하 패턴 금지)
8. 측정 지표 — 푸시 opt-in 률, opt-out 률, 알림→세션 완료율, 드롭오프
9. A/B 테스트 가드레일 — 안전 관련 알림은 A/B 금지

## 6.3 01-F 디자인 시스템·접근성 가이드

**목적**: WCAG 2.2 AA + KS X ISO/IEC 40500 준수, Apple HIG / Material 3 정합.

**목차 골격**:
1. 컬러 시스템 (라이트·다크·고대비)
2. 타이포그래피 (Pretendard / Noto Sans KR, 동적 타입 24pt까지)
3. 스페이싱·그리드 (4dp 베이스)
4. 컴포넌트 라이브러리 (Button, Card, Slider, Modal, Toast, Banner)
5. 모션 — Reduce Motion 대응
6. 접근성 — VoiceOver/TalkBack 라벨 표준, 색맹 형태/패턴 병기, 한 손 모드
7. 청각장애 사용자 — 피치 시각화 강조, 햅틱 보조, 자막 표준
8. 한국어 타이포 특수성 (조사 처리, 숫자·단위 띄어쓰기)

## 6.4 01-G 콘텐츠 제작 핸드북 (영상·오디오 PD용)

**목적**: 외주·내부 PD가 일관된 품질·톤으로 콘텐츠를 생산하기 위한 표준.

**목차 골격**:
1. 톤 매뉴얼 — 1인칭 코치, 평어체, 격려 빈도, 금지 표현(진단/치료/회복/극복/완벽)
2. 영상 SOP — 카메라(4K30, 4각도), 조명, 마이크(콘덴서 vs 다이내믹), 입 클로즈업
3. 오디오 SOP — 24bit/48kHz, 노이즈 플로어 −60dB ↓, 룸톤
4. anti-pattern 카탈로그 (절대 보여주면 안 되는 잘못된 폼·과장된 결과 시연)
5. 콘텐츠 라이프사이클 — 작성 → SLP 검수 → 시범 촬영 → A/B → 정식 → 사후 모니터링
6. 자막 작성 가이드 (1줄 16자, 색맹 대비)
7. 음성 액터 캐스팅 기준 — 한국어 표준어, 정서적 중립, 다양성(성별·연령) 고려
8. 14개 훈련 카드 풀 예시 5개 (P3-13 + 4개 추가)
9. 이해상충 정책 — PD 본인이 강사 등록 시 회피
10. 콘텐츠 검수 위원회 결재서 양식

## 6.5 01-H 운영 SOP (인시던트·고객지원)

**목적**: 출시 이후 운영의 모든 케이스 매뉴얼화.

**목차 골격**:
1. 인시던트 등급 정의 (P0 안전 위험·P1 결제·P2 기능·P3 UX)
2. 인시던트 대응 흐름 — 감지 → 1차 대응 → 위원회 통보(P0) → 사용자 통보 → 사후 분석
3. 적색 신호 false positive 인시던트 처리 (Part 3 §6 참조)
4. 사용자 통증·이상 호소 신고 SOP — SLP 위원 30분 내 검토, 후속 콘텐츠 차단
5. 환불·구독 취소 정책 (한국 전자상거래법 7일 청약철회, 디지털 콘텐츠 예외 명시)
6. CS 매크로 (한국어 30개) — 적색 신호 후속, 환경 분석 신뢰성, 마이크 권한 등
7. 콘텐츠 회수 SOP — 위원회 의결 후 24h 내 비활성화, 사용자 통지
8. 데이터 침해 통지 (PIPA 72h, GDPR 72h)
9. 외부 신고(식약처·PIPC·KCC) 절차

## 6.6 01-I 측정·분석 계획 (애널리틱스 이벤트)

**목적**: 출시 전부터 지표·이벤트 taxonomy를 사전 설계 — 사후 추가는 데이터 손실.

**목차 골격**:
1. 핵심 KPI 정의 — Day-1/7/30 리텐션, 일일 활성 사용자(DAU), 활성화율(첫 세션 완료), 24주 완주율(북극성 지표)
2. 이벤트 명명 규칙 (snake_case, object_action 형식)
3. 이벤트 카테고리:
   - **Onboarding**: `onboarding_start`, `onboarding_step_complete`, `onboarding_drop`, `consent_granted`(별도 동의 항목별)
   - **Session**: `session_start`, `card_start`, `card_complete`, `self_check_submit`, `session_complete`, `session_abort`
   - **Safety**: `red_flag_trigger`, `red_flag_user_response`, `red_flag_session_paused`, `red_flag_session_resumed`
   - **AI Analysis**: `analysis_low_confidence`, `analysis_user_disagree`(자가↔AI 충돌)
   - **Content**: `card_view`, `card_replay`, `feedback_thumbs_up/down`
   - **Habit**: `streak_start`, `streak_milestone`, `streak_freeze_used`, `streak_disabled`
   - **Monetization**: `paywall_view`, `trial_start`, `subscription_purchase`, `subscription_cancel`
4. 사용자 속성 — 가명 ID, 가입일, 디바이스, 마이크 모델, 옵트인 동의 여부
5. 분석 도구 비교 — Mixpanel(빠른 셀프서비스, 이벤트 기반 100K MTU 무료) vs Amplitude(예측 코호트, AI 자동 인사이트, 학습 곡선 가파름) — **권고: V1은 Mixpanel(빠른 도입), V2 데이터 누적 후 Amplitude 전환 검토**
6. 이벤트 거버넌스 — 신규 이벤트 PR 리뷰, taxonomy 변경 통지
7. 프라이버시 — IDFA·ADID 사용 X(가명 ID만), Mixpanel/Amplitude IP 익명화 옵션 ON
8. **안전 관련 메트릭**(일반 KPI와 별개): false positive 적색 신호율, AI 신뢰도 분포, 사용자 disagree 율 — 분기 위원회 보고 의무

- **Mixpanel vs Amplitude**: Mixpanel Growth 100K MTU 무료, 빠른 도입; Amplitude 예측 코호트·AI 분석, 학습 곡선 가파름·엔터프라이즈 가격.

## 부록 B. 본 보고서가 *반영하지 않은* 추측·전망

- **DMPA 하 본 앱의 정확한 분류 판정**: MFDS 자가판단 흐름도·법무 검수 *결과*에 따라 결정. 본 보고서는 "디지털의료·건강지원기기 또는 일반 웰니스 앱" 후보로만 제시.
- **AI 기본법 "고영향 AI" 적용 여부**: 시행령(2025년 말 발표 예정)에 따라 변동. 본 보고서는 "베스트 프랙티스 적용 권고"로 보수적 접근.
- **24주 완주 시 학습 효과 RCT 결과**: 자체 데이터 누적 전이며, 컨슈머 보컬 앱의 RCT는 부재. V2에서 자체 RCT 발표 제안만 가능.
- **콜드스타트 모델 정확도**: 베이스라인 PCC 0.5–0.7, F1 0.65 추정치는 공개 데이터셋 영어 기반 추정. 한국어 실측 시 조정 필요.
